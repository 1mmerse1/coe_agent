# 公众号文章入库实现规划

## 目标

把学生会公众号已发布文章按 URL 导入一套可回查、可去重、可重跑解析的数据库，为后续的历史文章检索、文案生成和排版模板提取提供可靠数据。

首期采用 **URL 驱动**：管理员粘贴单篇文章链接，或上传一列链接的 CSV。先把“给定文章链接，完整入库”做稳；自动枚举公众号所有历史文章列表是另一个问题，后续再单独评估官方后台导出、授权接口或人工整理等来源。

## 参考推送的观察

对提供的参考文章做了一次只读抓取，页面可返回 HTTP 200。观察到：

- 样例链接：[工启卓航系列讲座｜Bioelectronics: From Fundamental Research to Clinical Translation](https://mp.weixin.qq.com/s/2SkyyFMax1IslGmj5T7k_Q)。
- 标题在 `og:title` 元数据中，可解析为“工启卓航系列讲座｜Bioelectronics: From Fundamental Research to Clinical Translation”。
- 发布时间可由页面的 Unix 时间字段解析；样例显示为 2026-09-22 20:36（北京时间）。
- 正文可从 `#js_content` 定位，结构较长且含多个主题段落。
- 正文包含 21 个图片节点；文章结构包含讲座介绍、人物背景、主题小节、序号和中英文混排。
- 排版由大量嵌套节点和 inline `style` 组成，不能仅保存纯文本，也不应把正文压平成单一段落。

这说明第一版应保留原始正文 HTML、抽取纯文本、记录有序内容区块，并独立归档图片。样例验证只证明这一篇当前可读，不能据此保证所有公众号文章、历史页面及图片地址都始终可访问。

## 首期范围

### 做

1. 导入单篇文章 URL。
2. 支持 CSV 批量提交 URL，后台逐篇处理并显示状态。
3. 提取标题、来源 URL、发布时间、公众号名称（可得时）、摘要/封面（可得时）、原始正文 HTML、纯文本、图片及有序区块。
4. 按规范化 URL 去重；重复导入返回已有文章或重跑失败任务，不产生重复文章。
5. 保存抓取快照和解析器版本，允许升级解析器后离线重解析。
6. 图片下载到本地媒体目录；为未来 OSS/S3 迁移保留独立存储接口。
7. 单篇失败可查看错误、重试；图片失败不阻断正文入库。

### 暂不纳入

- 输入公众号名称后自动找到并枚举全部历史文章。
- 从文章反推原始秀米工程文件或可编辑秀米组件。
- AI 分类、向量检索、内容生成。
- 公众号自动发布。

## MVP 用户流程

```text
管理员粘贴文章链接 / 上传 URL CSV
                  ↓
              创建导入任务
                  ↓
  获取页面 → 快照 → 元信息和正文解析
                  ↓
       图片下载与 URL 替换（尽力完成）
                  ↓
   保存文章、图片、区块和导入结果
                  ↓
     管理员预览并修正分类/元信息
```

每个任务展示 `pending / fetching / parsing / completed / partial / failed` 状态。`partial` 表示正文已入库，但某些图片或可选元数据未取到。

## 建议架构

```text
导入入口（命令行 / 双击批处理）
        ↓
本地文章库文件（SQLite）
        ↓
单个后台 worker（首期无需 Celery）
        ├─ URL 校验与规范化
        ├─ 微信文章页面抓取
        ├─ 元数据与正文解析
        ├─ 图片下载 / 去重 / 本地化
        └─ 事务写库与状态更新
```

当前落地版采用 Python、requests、BeautifulSoup + lxml 和 SQLite。SQLite 是一个随程序保存在电脑上的数据库文件，不需要单独安装数据库服务，也不要求使用者编写 SQL。文章图片和网页备份放在 `data/` 文件夹；当需要多人同时使用或部署网站时，再迁移到 PostgreSQL 和 API 服务。首版使用轻量后台处理，不额外安装任务队列。

抓取器、解析器、媒体存储和数据库写入分层。微信页面结构调整时，只需更新 `WechatArticleParser`，不改 API 和存储流程。

## 处理步骤

### 1. 校验和规范化 URL

- 只接受 `https://mp.weixin.qq.com/s/...` 文章链接。
- 去掉无关追踪参数，保留能够唯一识别文章的路径/必要参数。
- 对同一规范化 URL 建唯一约束。
- 页面跳转后的最终 URL 也写入来源记录，方便追踪。
- 下载图片时只允许微信文章和图片 CDN 的明确域名白名单，限制响应大小和超时，避免任意 URL 下载。

### 2. 抓取并留存快照

- HTTP 客户端设置连接/读取超时、合理重试和有限并发。
- 记录抓取时间、HTTP 状态、最终 URL、响应哈希、解析器版本及错误信息。
- 保留原始页面快照，建议压缩后放本地归档目录或对象存储；数据库只存快照路径和哈希，避免把完整页面脚本重复塞进主表。
- 文章正文 HTML 另外存入文章记录，后续不依赖重新抓取页面即可重新解析。

### 3. 解析元数据

按优先级取值，并记录字段来源：

| 字段 | 首选来源 | 缺失处理 |
|---|---|---|
| 标题 | `og:title` | 标记待人工补充 |
| 文章 URL | 最终 URL | 必填 |
| 发布时间 | 页面时间字段（如 `ct`） | 为空，待人工补充 |
| 公众号名称 | 页面初始化数据中的昵称字段 | 为空，待人工补充 |
| 摘要 | `og:description` 或页面字段 | 允许为空 |
| 封面图 | `og:image` | 允许为空，按普通图片资产处理 |

不要依赖单一 CSS selector 或页面私有字段永久不变；解析器应返回字段级警告，并保存 `parser_version`。

### 4. 解析正文

优先找 `#js_content`。若没有命中，保存快照并将任务标记为 `failed`，错误为“未找到正文容器”，进入人工排查队列，不静默写入空文章。

正文处理产生三种结果：

1. `content_html_raw`：从正文容器截取的未改写 HTML，供排版分析和重解析。
2. `content_html_local`：只做必要清理和图片地址替换的 HTML，尽量保留标签、层级与 inline style。
3. `content_text`：按区块顺序抽取的纯文本，便于搜索和后续向量化。

另生成有序 `blocks_json`，首期识别 `heading / paragraph / image / list / quote / divider / unknown`。规则无法判断的内容标记 `unknown` 并保留 HTML，不用 AI 猜测。标题识别规则要保守，避免把加粗正文误分类为标题。

### 5. 图片下载与本地化

- 图片 URL 优先取 `data-src`，再取 `src` 等候选属性。
- 下载失败记录在图片行及任务警告中，继续处理正文。
- 以文件 SHA-256 去重，保存源 URL、MIME、字节数、宽高、哈希和本地路径。
- 下载成功后，将 `content_html_local` 中的图片 URL 换成内部媒体 URL/路径；原始 HTML 中的微信 URL 保持原样。
- 限制图片类型和大小；不接受 SVG/脚本等非预期内容。

## 数据表草案

### `articles`

| 字段 | 用途 |
|---|---|
| `id` UUID PK | 内部 ID |
| `source_url` TEXT UNIQUE | 规范化后的原文链接 |
| `final_url` TEXT | 实际跳转后的链接 |
| `account_name` TEXT NULL | 公众号名称 |
| `title` TEXT | 标题 |
| `published_at` TIMESTAMPTZ NULL | 发布时间 |
| `summary` TEXT NULL | 摘要 |
| `cover_image_id` UUID NULL | 封面图片 |
| `content_html_raw` TEXT | 正文原始 HTML |
| `content_html_local` TEXT | 图片本地化后的正文 HTML |
| `content_text` TEXT | 纯文本 |
| `blocks_json` JSONB | 有序区块 |
| `parser_version` TEXT | 解析器版本 |
| `import_status` TEXT | `completed / partial / needs_review` |
| `created_at`, `updated_at` | 入库时间 |

### `article_images`

保存 `article_id`、顺序、角色（正文/封面/未知）、原始 URL、存储路径、SHA-256、MIME、字节数、宽高、下载状态和错误。

### `article_import_jobs`

保存输入 URL、规范化 URL、状态、尝试次数、错误码/信息、警告 JSON、创建/开始/完成时间、关联文章 ID。对规范化 URL 建索引，以实现幂等和任务恢复。

### `article_snapshots`

保存文章/任务 ID、抓取时间、HTTP 状态、最终 URL、快照路径、哈希和抓取器版本。原始快照建议文件/对象存储，数据库保存索引信息。

首期先不建独立 `article_blocks` 表：区块数量随文章变化，放 JSONB 够用；确认后续要对区块做独立筛选和分析，再迁移为子表。

## 后续网站版 API 草案

首版用本地脚本导入，不要求打开终端以外的新服务。多人共用或增加网页管理页时，再按下面接口扩展：

```http
POST /api/article-imports
{ "url": "https://mp.weixin.qq.com/s/..." }

POST /api/article-imports/batch
{ "urls": ["...", "..."] }

GET /api/article-imports/{job_id}
GET /api/articles/{article_id}
POST /api/article-imports/{job_id}/retry
```

API 接收请求后快速返回任务 ID；抓取和图片处理由 worker 执行。前端轮询任务状态即可，避免 HTTP 请求等待整篇文章和多张图片下载完毕。

## 里程碑

### M0：解析验证

- 固定参考文章及若干本公众号不同年份文章作为样本。
- 验证标题、发布时间、正文、图片 URL、区块顺序和样式保留。
- 输出每篇字段命中率、正文字符数、图片数和解析警告。

### M1：单 URL 导入闭环（当前落地）

- Python 导入入口、本地 SQLite 文件、一个轻量后台处理器。
- 实现 URL 校验、快照、解析、媒体存储、去重、失败重试和文章预览。
- 验收：至少 20 篇文章可导入；重复提交不重复建文；正文缺失和图片失败有明确状态。

### M2：历史批量导入（当前落地）

- CSV 上传、并发限速、进度页、失败任务导出/重试。
- 先由管理员提供文章 URL 列表，不把公众号历史列表发现混入 importer。
- 验收：至少 100 个 URL 可分批导入，服务重启后队列可继续。

### M3：质量修正与后续接入

- 管理员编辑公众号名、文章类型、活动名称和标签。
- 根据真实失败样本迭代解析器并离线重跑快照。
- 后续再接活动主数据、RAG 和秀米模板归纳。

## 验收指标

- 样本中标题提取率 ≥ 98%；正文容器命中率 ≥ 95%。
- 文本内容与页面人工抽查一致，段落和图片顺序不乱。
- 原始正文 HTML 可追溯；解析器升级后可重跑。
- 同一 URL 多次提交保持幂等。
- 单张图片失败不影响标题和正文入库，失败可定位及重试。
- 全量处理结果可按 `completed / partial / failed` 查询和导出。

## 主要风险和处理

| 风险 | 处理方式 |
|---|---|
| 微信页面结构变化 | Parser 单独版本化；保存快照；字段级报警和重解析 |
| 历史文章或图片访问失败 | URL 导入为主；记录部分成功；支持人工补充或重试 |
| URL 获取方式受权限或平台策略限制 | 不假定存在稳定的公开“按公众号 ID 拉全量文章”接口；来源发现单独评估 |
| 秀米 DOM 层级复杂 | 保留正文 HTML 与 inline style；分块解析失败时保留 unknown 原始块 |
| 微信图片链接失效 | 下载副本并存内容哈希；失败单独标记，不覆盖原始 URL |
| 大批量导入触发限制 | 低并发、任务限速、指数退避；先验证小批次 |
| 页面含非预期 URL 或大文件 | 文章/图片域名白名单、超时、内容类型和体积限制 |

## 当前建议

先做 M0 + M1。开发前准备 20 篇代表性文章 URL，覆盖不同年份、排版风格、图文长度和活动类型。参考文章适合做复杂度样本：正文较长、图多、含中英文和多级排版。用这批样本验证解析器后，再开始 100 篇以上批量入库。
