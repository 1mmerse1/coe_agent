# 推送 Agent 本地调试

## 1. 准备环境

在 PowerShell 中进入项目目录：

```powershell
cd C:\Users\17611\Desktop\coe_agent
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

确认根目录 `.env` 至少包含：

```text
LLM_PROVIDER=aizex
LLM_API_KEY=你的密钥
LLM_BASE_URL=https://codex-api.aizex.net/v1
LLM_API_MODE=auto
# Luna 暂不可用，Luna 角色临时使用 Sol-low
OPENAI_MODEL_LUNA=gpt-6-sol
OPENAI_MODEL_SOL=gpt-6-sol
OPENAI_REASONING_LUNA=low
OPENAI_REASONING_SOL=high
# 当前版本已取消 APP_ACCESS_CODE
```

## 2. 启动开发服务器

推荐开发时使用自动重载：

```powershell
python -m uvicorn app:app --app-dir src --reload --host 127.0.0.1 --port 8000 --ws none
```

浏览器打开 <http://127.0.0.1:8000>。生产式运行或局域网共享继续使用 `启动推送助手.bat`。

## 3. 先测框架，不调用模型

打开另一个 PowerShell 窗口。当前版本不需要访问码，直接测试状态接口：

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/status
```

然后测试流程清单：

```powershell
$manifest = Invoke-RestMethod http://127.0.0.1:8000/api/workflow/manifest -WebSession $session
$manifest.agents.push_agent
$manifest.flows.planning.stages
```

未设置访问码时，去掉 `-WebSession $session` 即可。应看到 `push_agent`，并看到四个并列下游：`push_agent|poster_agent|survey_agent|ppt_agent`。

也可以单独测试 Router：

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/workflow/route `
  -Method Post -WebSession $session -ContentType 'application/json' `
  -Body '{"task_type":"push"}'
```

应返回 `agent: push_agent`、`configured_model: gpt-6-sol`。把 `task_type` 改为 `poster`、`survey` 或 `ppt`，可以检查另外三个并列分支。

## 4. 调试推送 Agent 和 HTML 预览

活动工作台的三步接口可以这样调试：

```powershell
$brainstorm = Invoke-RestMethod http://127.0.0.1:8000/api/activity/brainstorm `
  -Method Post -WebSession $session -ContentType 'application/json' `
  -Body (@{ raw_input = '大家讨论要为新生办一场交流活动，帮助新生认识彼此；时间和地点还没有确定。'; extra_context = '希望活动轻松、控制在两小时内。' } | ConvertTo-Json)

$facts = $brainstorm.result | ConvertTo-Json -Depth 10
$plan = Invoke-RestMethod http://127.0.0.1:8000/api/activity/plan `
  -Method Post -WebSession $session -ContentType 'application/json' `
  -Body (@{ brainstorm = $facts; additions = '希望安排分组交流和报名环节。'; style = '清晰、稳妥、可执行' } | ConvertTo-Json)

$planning = $plan.result | ConvertTo-Json -Depth 10
$content = Invoke-RestMethod http://127.0.0.1:8000/api/activity/content `
  -Method Post -WebSession $session -ContentType 'application/json' `
  -Body (@{ planning = $planning; content_types = @('push','poster'); theme = '新生交流活动'; requirements = '推送语气亲切，海报突出活动主题。'; reviewer = '测试人' } | ConvertTo-Json -Depth 10)

$content.result.items | Select-Object type,model,preview_url
```

第三步的 `content_types` 可选 `push`、`poster`、`survey`、`ppt`，也可以只选择一个。

## 5. 调试拖入文件和 Brainstorm 建议 Agent

浏览器页面的 Brainstorm、策划和内容制作区域都有拖入区。PDF、DOCX、XLSX、PPTX、ODT、ODS、ODP 由本地服务提取文字；扫描版 PDF 的前 6 页会作为图像交给视觉模型。TXT、Markdown、CSV、JSON 等纯文本读取前 30000 字符，每份文件最多取前 6000 字进入 Agent 提示词。图片会作为视觉输入发送。单文件限制 12 MB，超过时页面会提示且不会上传。Brainstorm 底稿在页面上以可编辑卡片展示，必要时可展开原始 JSON。

侧栏建议 Agent 接口：

```powershell
$context = @"
Brainstorm 底稿：新生交流活动，时间待确认
策划案：需要安排分组交流
内容要求：推送语气亲切
"@

Invoke-RestMethod http://127.0.0.1:8000/api/activity/brainstorm/chat `
  -Method Post -WebSession $session -ContentType 'application/json' `
  -Body (@{ message = '下一步还应该确认什么？'; context = $context; history = @() } | ConvertTo-Json -Depth 10)
```

该 Agent 的建议不会自动写回活动资料，用户确认后再手动修改底稿或策划案。

## 6. 活动历史和策划案导出

点击左侧“新建活动”会创建一条新的本地活动记录；活动历史显示在左侧目录。输入、附件、Brainstorm 底稿、策划案以及内容制作结果自动保存在 `data/activity_projects.sqlite3`，附件保存在 `data/activity_files/`。重新打开页面会载入上次使用的活动。

策划阶段可手动选择详细版、中等版、简洁版或自动匹配。范例文字和编写要求位于 `resources/planning_templates/`。生成策划案后，页面提供 Word/PDF 下载链接。修改正文卡片后点击“按当前修改重新导出”，可更新供人工审阅的文档。导出文件保存在 `data/activity_exports/`。

## 7. 本地图片素材检索

内容制作阶段会自动从 `data/` 的学院素材目录，以及 `data/media/` 中已入库的历史推送图片里检索相关图片。图片通过 `GET /api/library/images?q=活动主题` 列出，缩略图由 `GET /api/library/images/{id}/preview` 提供。候选可以在页面勾选或取消，最多 4 张；勾选图片会转换为 JPEG 数据发送给图文、海报和 PPT Agent。历史推送图只作为视觉参考。若推送 Agent 选用已勾选的可复用学院素材，生成的 HTML 会嵌入该图。无法读取的 PSD 或 AI 文件需先导出 JPG/PNG 预览。

如果模型接口返回 `401 Unauthorized`，请检查当前 clone 的 `LLM_API_KEY`、`LLM_PROVIDER`、`LLM_BASE_URL` 和模型名；页面本身不再需要访问码。

```powershell
$body = @{
  event_time = '2026-10-01 14:00'
  location = '学院报告厅'
  theme = '新生交流活动'
  push_type = '预热'
  audience = '2026级新生'
  activity_intro = '面向新生的交流活动，具体流程以审核后的策划案为准。'
  plan = '活动目标：帮助新生了解学院；流程和报名方式待确认。'
  reviewer = '张老师'
  assets = @()
} | ConvertTo-Json -Depth 5

$result = Invoke-RestMethod http://127.0.0.1:8000/api/generate-push-html `
  -Method Post -WebSession $session -ContentType 'application/json' -Body $body

$result.agent
$result.model
$result.preview_url
$result.download_url
$result.xiumi_html.Substring(0, [Math]::Min(300, $result.xiumi_html.Length))
```

把 `$result.preview_url` 拼到 `http://127.0.0.1:8000` 后在浏览器打开，例如：

```text
http://127.0.0.1:8000/graphic-previews/xiumi-push-xxxx.html
```

检查重点：

- 返回的 `agent.agent` 是 `push_agent`；
- `model` 通常是 `gpt-6-sol`；
- 页面能打开，标题、正文、活动信息、署名和图片占位正常；
- 未提供的事实保留 `[待确认]` 或 `[待填写]`；
- `xiumi_html` 能复制到秀米继续编辑。

如果没有设置访问码，删除这条命令中的 `-WebSession $session`。

## 6. 常见问题定位

| 现象 | 先检查 |
|---|---|
| 页面打不开 | 8000 端口是否被占用，服务器窗口是否有 traceback |
| 返回 401 | 登录 Cookie 是否保存在同一个 `$session` 中 |
| 返回 503 | `.env` 是否有 `LLM_API_KEY`，以及 `LLM_PROVIDER`、`LLM_BASE_URL` 是否匹配 |
| 返回 502 | 模型权限、Base URL 和服务器窗口中的原始错误 |
| HTML 能生成但图片缺失 | 先确认图片 URL 或上传素材，再调图片生成 |
| 模型把历史文章当事实 | 检查 Agent prompt 是否明确“历史资料只是参考”，并保留人工复核 |
