# 数据库和素材共享方案

## 当前数据规模

本地数据分为两部分：

- `data/articles.sqlite3`：历史公众号推送的文章、原文链接、正文、HTML 和图片索引，约 9 MB。
- `data/media/` 与 `data/articles/`：历史推送使用的图片和本地预览，当前约 155 MB。
- `data/学校学院/`、`data/过渡图标/`：可复用素材，当前约 23 MB。
- `data/activity_projects.sqlite3`：本机“办一场活动”的草稿和生成结果，包含本地人员输入，默认不共享。

## 短期共享方式：共享数据包

当前采用的实际流程是：代码通过 GitHub 共享，你把当前历史数据库和指定图片素材另行压缩后发给合作者；合作者 clone 仓库后，把压缩包中的 `data/` 复制到项目根目录，再在自己的 `.env` 中填写自己的模型 API Key。这样每个人都有一份本地只读历史库和独立的活动草稿。

代码通过 GitHub 共享，数据通过单独的数据包共享。运行：

```powershell
python src\export_shared_bundle.py --output D:\coe_shared
```

默认数据包包含：

- 全部历史推送数据库 `articles.sqlite3`；
- 历史推送图片 `media/` 和文章预览 `articles/`；
- `学校学院/` 和 `过渡图标/` 两个可复用素材文件夹；
- `manifest.json`，记录文件大小和 SHA-256 校验值。

数据包不包含 `.env`、API Key、活动附件、生成文件和预览缓存。需要增加其他素材时可以重复传入参数：

```powershell
python src\export_shared_bundle.py --output D:\coe_shared `
  --folder 学校学院 --folder 过渡图标 --folder 迎新专用
```

数据包适合放在学院网盘、OneDrive、阿里云 OSS、腾讯 COS 或服务器对象存储中，再把下载地址和校验值发给团队成员。不要把包含 API Key 或个人活动草稿的数据包上传到公开 GitHub。

## GitHub 的边界

GitHub 仓库只保存程序、模板、提示词和导出脚本。SQLite 文件可以作为 Release 附件或私有对象存储文件，但不建议频繁提交到 Git 历史；图片素材也不建议直接提交普通 Git。若以后要把素材版本纳入 Git 管理，可单独使用 Git LFS，但需要核算存储和下载额度。

## 运行端安装共享数据

把共享包中的 `data/` 合并到项目根目录的 `data/`，再启动程序。多个电脑都使用同一份只读历史推送库时不会互相覆盖；每台电脑的活动草稿仍保存在本机。

## 中长期多人协作

如果需要多人同时新增活动、修改历史文章或管理素材，建议升级为：

1. PostgreSQL 保存文章、活动、模板和权限等结构化数据；
2. 对象存储保存原图、PDF、DOCX 和生成文件；
3. 数据库只保存文件 ID、版本、来源和哈希；
4. API 服务统一处理检索、权限和写入；
5. GitHub Actions 或定时任务生成脱敏备份和只读数据包。

SQLite 适合单机和少量只读副本，不能作为多人同时写入的网络共享数据库。
