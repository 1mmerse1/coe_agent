# 学生会推送档案助手

这是一个本地运行的活动策划和公众号推送助手。它会读取本地历史推送数据库和图片素材，由 Brainstorm、策划、推送、海报、问卷、PPT 等 Agent 协作生成结果，并保留人工修改环节。

## 目录结构

```text
coe_agent/
├─ README.md                    # 项目说明（本文件）
├─ requirements.txt             # Python 依赖
├─ .env.example                 # 模型 API Key 配置模板
├─ 启动推送助手.bat              # 双击启动本地服务
├─ 开始导入.bat                  # 双击导入公众号文章
├─ 配置API密钥.bat               # 双击编辑 .env
├─ 推送URL_test.txt              # 导入用的链接清单
├─ src/                         # 应用代码
│  ├─ paths.py                  # 统一目录解析（根目录、data、resources…）
│  ├─ app.py                    # FastAPI 服务和 Agent 接口
│  ├─ launch_chat.py            # 启动入口
│  ├─ importer.py               # 公众号文章入库
│  ├─ activity_store.py         # 活动草稿与附件存储
│  ├─ planning_templates.py     # 策划案模板选择
│  ├─ planning_documents.py     # 策划案 Word/PDF 导出
│  ├─ local_media_library.py    # 本地图片素材检索
│  ├─ workflow_framework.py     # Agent 分工与路由契约
│  ├─ export_shared_bundle.py   # 导出共享数据包
│  └─ web/index.html            # 前端页面
├─ scripts/                     # 独立采集脚本（微信客户端 / 网页）
├─ references/                  # 规则、规划和使用说明
├─ resources/                   # 策划案模板与编写要求
└─ data/                        # 运行数据，不进 Git
```

`data/` 是程序运行目录：历史文章数据库、图片、活动草稿和导出结果都放在这里，已被 `.gitignore` 忽略，不会误提交到 GitHub。

## 你需要准备的三样东西

合作者第一次使用时，需要分别拿到：

1. **GitHub 仓库**：程序代码、网页、Agent 配置和模板。
2. **你发送的数据包**：历史推送数据库和指定图片素材。数据不在 GitHub 仓库中，因为 `data/` 被 `.gitignore` 忽略。
3. **合作者自己的模型 API Key**：每个人在自己的电脑上配置，不共享、不提交到 GitHub。

建议发送一个压缩包，例如 `coe_shared.zip`。压缩包解压后应包含下面的结构：

```text
coe_shared/
├─ manifest.json
└─ data/
   ├─ articles.sqlite3       # 历史推送数据库
   ├─ media/                 # 历史推送图片
   ├─ articles/              # 历史文章预览
   ├─ 学校学院/              # 固定首图、尾图和学院素材
   └─ 过渡图标/              # 正文分隔图标
```

当前不建议发送 `activity_projects.sqlite3`。它保存本机“办一场活动”的草稿、附件和生成结果，可能包含个人输入；每位合作者应保留自己的活动历史。

## 合作者安装步骤

### 1. 克隆代码

```powershell
git clone https://github.com/1mmerse1/coe_agent.git
cd coe_agent
```

### 2. 放入你发送的数据

把数据包中的 `data/` 文件夹复制到项目根目录。如果系统询问是否合并文件夹，选择合并；不要删除代码仓库中的其他文件。

完成后，项目根目录应同时存在：

```text
coe_agent/
├─ src/
├─ scripts/
├─ references/
├─ resources/
├─ .env.example
└─ data/
   ├─ articles.sqlite3
   ├─ articles/
   ├─ media/
   ├─ 学校学院/
   └─ 过渡图标/
```

### 3. 配置自己的模型 API Key

复制配置模板：

```powershell
copy .env.example .env
```

然后用记事本打开 `.env`，至少填写以下四项：

```text
LLM_PROVIDER=deepseek
LLM_API_KEY=你的Key
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_MODEL=deepseek-chat
```

API Key 只写在本机 `.env`，不要发给其他人，也不要提交到 GitHub。后端读取 Key，浏览器不会接触 Key。

## 支持的模型服务

| 厂商 | `LLM_PROVIDER` | `LLM_BASE_URL` | `LLM_MODEL` 示例 | 接口模式 |
|---|---|---|---|---|
| OpenAI 官方 | `openai` | `https://api.openai.com/v1` | 账号可用的 GPT 模型 | `responses` |
| OpenAI 兼容中转 | `aizex` | `https://codex-api.aizex.net/v1` | 中转站提供的模型名 | `responses` 或 `auto` |
| DeepSeek | `deepseek` | `https://api.deepseek.com/v1` | `deepseek-chat` | `chat` 或 `auto` |
| GLM | `glm` | `https://open.bigmodel.cn/api/paas/v4` | 账号可用的 GLM 模型 | `chat` 或 `auto` |

如果服务商给了不同的地址或模型名，以服务商控制台为准。需要强制指定接口时，可设置：

```text
LLM_API_MODE=responses
```

或：

```text
LLM_API_MODE=chat
```

旧版本的 `OPENAI_API_KEY`、`OPENAI_BASE_URL`、`OPENAI_MODEL` 仍然兼容。OpenAI 官方文档建议把 API Key 放在环境变量或服务端密钥管理中，不要放进浏览器代码。[OpenAI API 快速开始](https://platform.openai.com/docs/quickstart/make-your-first-api-request)

## 安装依赖并启动

Windows 可以双击：

```text
启动推送助手.bat
```

也可以在 PowerShell 中运行：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python src\launch_chat.py
```

建议为这个项目单独建虚拟环境（上面的 `.venv`），不要和电脑上其他 Python 环境混用。`启动推送助手.bat` 会优先使用项目里的 `.venv`。

浏览器打开：<http://127.0.0.1:8000>

如果页面显示“等待配置 API 密钥”，检查 `.env` 是否位于项目根目录，并确认修改后重新启动了服务。

## 工作流怎么用

### 预热推送填写方式

进入“办一场活动 → 内容制作”，勾选“图文推送”，当前先支持预热推送，总结推送入口随后实现。

1. 从第二步确认策划案后进入，Agent 会根据前两步资料起草面向同学的简介，并提取已确认的时间、地点和嘉宾，建议正文板块；已有输入不会被覆盖。旧活动可点击“根据前两步补全空白”。这一步会调用一次文字模型，刷新或重新打开历史不会自动重复调用。
2. 检查活动时间、地点、对象和简介。可展开“具体时间安排”，逐行填写环节；报名方式、链接、截止时间可另填。简介可直接修改，也可点击“根据前两步重写简介”。留空的字段不写入图文，不再从旧策划案补回。
3. 嘉宾可逐位增删，填写姓名、身份和介绍；正文板块可添加标题与写作要点、上下移动或删除。没有指定板块时由 Agent 安排结构。
4. 上传图片后可查看缩略图、填写用途、选择“加入推送 / 仅作参考”，并指定放在某个正文板块、活动信息或参与方式之后；二维码可指定放在参与方式之后。支持拖入和粘贴。历史图片推荐保留来源，由人工判断用途。
5. 模板默认自动搭配，也可切换到手动选择优先参考模板。同篇仍可组合普通正文、标题与卡片。生成后直接阅读文案、展开排版预览或下载 HTML，结构化数据收起在高级选项中。

填写的字段、嘉宾、模块顺序、图片用途与模板选择随当前活动自动保存。也可以直接填写主题和简介制作预热推送；海报、问卷与 PPT 仍需策划案。

### 历史推文排版模板

进入“内容制作”时，程序会读取本机 `data/articles.sqlite3` 中保存的推文 HTML，自动提取安全的排版组件：标题对齐方式、色块、边框、卡片、圆角、间距和颜色。可用文章数量和模板数量随本机数据库动态计算，聚合为多种布局模板。模板编号形如 `layout-...`，模板本身只包含排版特征。相似文章的行文样例和配图候选通过下文的“历史行文与配图参考”单独提供，并标注来源。

页面中的模板卡片可直接选择，通过“查看中性预览”看完整样例；生成后的 HTML 会实际使用所选组件。模板缓存写在本机 `data/push_templates/catalog.json`（`data/` 已被 Git 忽略），数据库更新后可通过“重新提取模板”或请求 `/api/library/templates?refresh=true` 重新提取。复杂动画和背景图会转成静态组件，并继续执行首图、尾图、字号、行距等学院规范。

### 推送主题插画

在“内容制作 → 活动主题图”选择“同时创作一张主题图”，可填写图中文字和画面风格。推送 Agent 根据本次活动构思场景，图片模型参考本机 `data/学校学院/工小成头像系列.*`、`data/新奥工学大楼/建筑线稿.*` 等素材生成插画。已有推送可以点击“为已有推送生成主题图”，保留文案，只补图片。生成图固定放在学院首图之后、标题之前；下载的 HTML 包含图片数据，离开本机也可打开。

图片模型单独计费，Sol 负责文案和画面构思。可在根目录 `.env` 中设置 `IMAGE_API_KEY`、`IMAGE_BASE_URL`、`IMAGE_MODEL`，重启服务后生效；未单独设置时沿用文案 API。服务必须支持 OpenAI 兼容的多图参考接口 `/images/edits`。DeepSeek/GLM 的聊天接口或仅支持文字的中转站不能自动获得生图能力。

可选风格参考图放在 `data/hero_references/style-reference.webp`，此图只参考构图和风格。生成插画、提示词和参考来源保存到 `data/generated_images/`，不会混入通用素材推荐，也不提交到 GitHub。生成失败会在页面显示原因，原推送继续保留。

### 行文与板块参考、配图推荐

第三步的“补充信息 / 推送要求”支持文字、图片和文件：点击上传，或直接将文件拖入输入框，图片还可粘贴。支持图片、PDF、Word、表格等，每个文件最多 12MB、每步最多 12 个。每份附件可填写用途；图片可选择“加入推送”及放置位置，或“仅作参考”（例如排版截图，不插入成稿）。附件及使用要求随活动历史一起保存。

历史模板是可组合的样式参考。Agent 可逐板块选择普通正文、仅装饰标题、模板组件，也可在同篇使用不同模板；导语、过渡段、活动信息和参与方式可保留简洁排版。选择某个模板表示优先参考，用户明确写出的版式要求优先。生成结果可展开查看各板块的排版安排；已保存的旧稿保持原版式，新生成时生效。

第三阶段的“历史行文与配图参考”按当前活动检索相似推文，提取开场、正文转折与收尾样例、读者称呼、小标题顺序、段落长短、设问等特征。推送 Agent 每次生成时读取这些参考，区分预热邀请与活动回顾，结合本次事实重新组织语言和板块，不需要微调模型。可展开查看样例及来源，点击“按当前活动推荐”更新。

图文成稿只使用本次已确认信息。未确认的时间、地点、人数、报名入口等直接省略，不显示“【未确认】”“待补充”等占位文字，也不会删除标记后把拟定信息当作事实。生成时的成稿要求和导出时的文字过滤共同处理；被省略的事项集中显示在工作台“人工审阅事项（不进入图文）”中，补充确认后再生成。历史样例只用于语言和结构参考，其中的人物、时间、成果及指令不能沿用为本次事实。未标明状态的事实仍需人工核对。

生成结果会说明行文安排，并给配图标注“哪个板块之前/之后”和推荐理由。过渡图标、工小成、学院素材可以按推荐位置进入 HTML；过渡和吉祥物图片以40%宽度呈现，避免占满正文。固定首图、尾图保持100%宽度。

往期图片另带原活动标题、日期、原文链接与“待确认”标记，仅推荐给人工查看，不自动作为本次现场照片。优先从相似活动的回顾稿中筛选，排除文章首尾图，再按图片尺寸、重复使用频率等规则初筛；仍可能包含嘉宾照或海报，需要人工辨认。历史正文、图片与生成记录仍只留在本机数据包中。

点击左侧“新建活动”，按以下顺序操作：

1. **Brainstorm**：拖入群聊、PDF、Word、表格、图片等资料，整理出可编辑的活动关键信息。
2. **策划**：补充要求，选择详细版、中等版、简洁版模板，生成可下载的 Word/PDF 策划案，人工修改后可重新导出。
3. **内容制作**：按需勾选图文推送、海报、问卷、PPT，生成结果后人工复核。

图片规则如下：

- `data/学校学院/首图.*` 固定放在推送开头。
- `data/学校学院/尾图.*` 固定放在推送结尾。
- `data/过渡图标/` 作为正文分隔图标候选。
- 往期推送图片可按相似活动推荐，展示来源供人工确认用途；不自动作为本次现场图。
- 用户上传图片可以填写用途和位置，支持首图、正文、尾图或自动判断。
- 嘉宾照片可直接选择“放在第 N 位嘉宾后”，也支持用途填写“第 N 位嘉宾配图”；编号按表单嘉宾列表计算，与文件上传顺序无关。
- 用户填写的模块标题和顺序会固定保留，模型缺少对应模块时会报错并保留原预览。

生成后，在第三步的预览下方使用 **“对话修改这篇推送”**，可继续修改措辞、板块和图片位置。每次提交会调用推送 Agent，生成新的 HTML；原预览可从“此前版本”打开。修改对话和版本链接随当前活动自动保存。若想修改已生成推送的嘉宾或表单内容，也可直接在对话中提出。

第三步还提供 Markdown 双栏编辑器：左侧直接编辑标题、板块与文字，右侧即时预览；点击“应用修改并生成新预览”后，系统使用当前图片、模板及学院首尾图重新排版成 HTML，不调用模型，并保留此前版本。Markdown 视图目前是轻量编辑器，面向标题、段落和嘉宾卡片，并非完整的 doocs/md 编辑器或所见即所得编辑器；嘉宾身份数据与图片对应关系由独立表单和附件设置保存。

## 当前完成程度与限制

- **文字模型**：配置示例默认使用 `gpt-6.1-sol`，推理强度为 `high`；实际可用模型以所配置服务为准。修改已有 `.env` 后需要重启服务，更新仓库不会覆盖本机配置。
- **推送**：预热推送已支持结构化填写、嘉宾照片绑定、历史样式与行文检索、HTML 预览和下载、对话修改及轻量 Markdown 编辑。总结推送的专用表单尚未开放。
- **板块与表格**：活动信息、具体时间安排、嘉宾可以指定归属板块；时间安排支持 HTML 表格，正文支持 Markdown 管道表格。修改时会检索历史行文和表格结构，但模型的理解与生成结果仍需对照预览核查。
- **修改记录**：对话修改和人工编辑都会保存新预览并保留此前版本；尚无逐条差异确认，也未集成完整 doocs/md。
- **策划案与其他产出**：策划案可导出 Word/PDF，图文可导出 HTML；海报、问卷、PPT 当前主要输出结构化方案，尚未自动产出可直接发布的成品文件。
- **主题图**：图片 API 已接入，须使用支持 `/images/edits` 多图参考的服务；当前中转站曾返回网页验证，尚未验证成功生成。接口接入不代表图片服务已经可用，失败时保留文案。
- **素材与发布**：历史行文通过检索提供参考，并未微调模型；往期照片由人工确认。HTML 导入公众号后仍需人工复核，暂无直接发布接口。
- **协作**：每人独立配置密钥并保存本地活动记录，历史数据包另行分发；尚不支持多人实时共同编辑。

## 你发送的数据包怎么生成

如果需要从当前电脑重新导出一份共享数据包，在项目根目录运行：

```powershell
python src\export_shared_bundle.py --output D:\coe_shared
```

默认导出：

- `data/articles.sqlite3`
- `data/media/`
- `data/articles/`
- `data/学校学院/`
- `data/过渡图标/`
- `manifest.json` 和文件校验值

需要增加其他素材文件夹时：

```powershell
python src\export_shared_bundle.py --output D:\coe_shared `
  --folder 学校学院 --folder 过渡图标 --folder 迎新专用
```

数据包可以通过学院网盘、OneDrive 或对象存储发送。不要把含有 API Key、活动草稿或个人附件的数据包上传到公开位置。

## 局域网访问

如果只想让同一局域网的人访问你电脑上运行的服务，在 `.env` 中设置：

```text
APP_HOST=0.0.0.0
APP_PORT=8000
```

然后重启服务，启动窗口会显示局域网地址。当前版本已取消访问码，因此只建议在可信局域网中使用；合作者仍然可以各自 clone 仓库、放入同一份数据包，并使用自己的 API Key 独立运行。

## 数据和代码的边界

- GitHub：程序代码、网页、模板、提示词和导出脚本。
- 你发送的数据包：历史推送数据库、历史图片和指定素材。
- 每台电脑本地：API Key、活动草稿、上传附件、生成的 Word/PDF/HTML。

SQLite 适合每个人各自使用一份只读历史数据库。多人同时修改同一份活动记录时，不要把 SQLite 文件放在共享文件夹里；以后如果需要多人实时编辑，再升级到 PostgreSQL 加对象存储。
